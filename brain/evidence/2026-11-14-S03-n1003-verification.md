## 3) AC2 — Comando interno duplicado ⇒ un solo decremento + log observable

Inyección (mini-consola temporal que referencia `Shared.Infrastructure`, mismo transporte/CA):
`reserve-seats` para la compra pur-819e47f5... (ya TICKETS_ISSUED) con la MISMA correlación
(type+purchase_id) y dedup id DISTINTO (`reserve-seats:{pur}:s03-proof`) — simula un relay que
re-publica fuera de la ventana de dedup de SQS, forzando la entrega al handler.

```
disponibilidad ANTES del duplicado:  498
[inyección] → SQS lo ENTREGA (dedup id distinto)
disponibilidad DESPUÉS del duplicado: 498   ← un SOLO decremento total
```

Log REAL del proceso Catálogo (`catalog.log`, JSON console):
```
comando 'reserve-seats' de compra pur-819e47f5db9f4a5c919163cc51d6ddcd duplicado detectado:
efecto descartado (idempotencia por correlación)
```
El handler re-publicó `seats-reserved` hacia Órdenes; SQS FIFO lo tragó (mismo
`MessageDeduplicationId` que el evento original = capa 1 del dedup funcionando) — el
descarte por CAS del process manager queda cubierto en `SagaProcessManagerTests`
(redelivery de seats-reserved con compra no-PENDING → ignorado sin re-emitir comandos).

Integración (test `CatalogSagaDedupTests`, emulador real): envío doble con IGUAL dedup id →
SQS entrega 1; reenvío con dedup id distinto → el handler lo descarta; disponibilidad 5→3
(un solo decremento por 2 asientos × 1 reserva) + assert del log "duplicado detectado:
efecto descartado".

## 5) Desvíos y decisiones

- **422 (no 409) para mismatch de key y agotado**: lo fija plan §2/§S03 y D-0009; el prompt
  de S03 mencionaba 409/422 — prevalece el plan (documentado en D-0009 §4).
- **Replay exitoso = 200** (no 201): nada nuevo se crea (D-0009 §3).
- **Fix de tests heredados de la sesión previa de S03** (la suite llegaba rota; hoy 96/96 ×2):
  1. `OrdersApiTests` usaba key fija `api-test-key-1` — el claim persiste en el DynamoDB del
     emulador ⇒ 2ª corrida daba 200-replay en vez de 201. → key única por corrida.
  2. `OrdersIdempotencyApiTests` (heal de crash) hasheaba el claim con holder distinto al del
     body POSTeado ⇒ 422 determinista. → alineados.
  3. `CatalogSagaDedupTests` usaba la cola compartida `ticketflow-catalog-commands.fifo`: el
     worker del host de `CatalogApiTests` (clase paralela) le robaba mensajes ⇒ flaky. → cola
     FIFO dedicada por corrida (mismo transporte, mismos atributos). Registrado como L-008.
- Driver de servicios y mini-consola inyectora viven en `%TEMP%\opencode\s03-verify\` /
  `s03-inject\` (temporales, cero artefactos al repo); los scripts permanentes de demo son
  S04/N-1004.
