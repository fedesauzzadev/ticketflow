## Hallazgos del emulador
- Las managed policies de AWS existen (`AmazonEKSClusterPolicy`, etc.): los attachments funcionan.
- El node group crea un Auto Scaling Group y 2 instancias EC2 emuladas (`describe-instances` → 2).
- El endpoint del cluster sirve una API de Kubernetes emulada (`/version` → `"platform":"emulator"`),
  en un puerto ALEATORIO dentro del contenedor (solo 9297 está publicado → inalcanzable desde el host).
  `/api/v1/nodes` lista los 2 nodos del node group; hay grupos rbac/authentication.
- Un POST de Pod (nginx) fue aceptado y agendado a un nodo, pero pasó a `phase: Failed`:
  no ejecuta contenedores. DELETE de pods no está permitido → quedó un pod `probe` (Failed)
  en `default`, inofensivo, en memoria; desaparece al recrear el cluster o el contenedor.
- `aws eks update-kubeconfig --dry-run` genera un kubeconfig válido apuntando a ese endpoint.
- Kubernetes de Docker Desktop NO está habilitado en esta máquina (kubectl sin contextos):
  prerequisito pendiente para el nodo de manifiestos.
