# CI local: build + tests + cobertura en un comando, workflow de GitHub Actions como artefacto

Historia H-08 (parte CI) del backlog (slice v2). El repo NO tiene remote git:
el pipeline "de cada push" se materializa como (a) script de CI local ejecutable
que valida build+tests+cobertura en un comando — el gate que el dueño y el
evaluador pueden correr hoy — y (b) workflow de GitHub Actions versionado como
artefacto de portfolio, válido y documentado, que correría sin cambios si el
repo gana remote.

## Por qué absorbe F-V1-R3-01 (decisión PO)
Un gate de CI debe ser determinista también en una sesión local compartida
(emulador con DLQ sucia >10 entradas — exactamente el trigger del QA). Dejar el
flake fuera convertiría el stage de demos del CI en no confiable; el fix es
chico (peek por compra o paginación) y pertenece aquí, no en una historia propia.

## Notas de scope (PO)
- Cómo el runner real de GH Actions serviría el emulador (contenedor en el job,
  subset sin emulador documentado, o build del aws-emulator/) lo decide el TL;
  el AC exige workflow válido + documentación de esa decisión, no su ejecución
  (no hay remote donde correrlo).
- Fuente de verdad de ACs: factory/backlog.md H-08 (AC1..AC5 = parte CI).
- Reutiliza lo existente: extracción de env del emulador (run-local.ps1 §1-2),
  umbral de cobertura ya cableado (F-03/F-V1-04), gate probado rojo/verde (QA).

## Fuera de alcance
- IaC/aprovisionamiento declarativo (va en N-3002, misma H-08).
- Publicar el repo / crear remote / correr el workflow en un runner real.
